### 3.3 典型错误案例

1. **KeyError 'BMI'/'J'**: CoderAgent 生成的代码使用了错误的列名（可能是 Excel 列字母而非实际列名）

3. **ValueError only one class**: 女胎异常判定模型训练时，某个子任务的数据子集只包含单一类别
4. **ValueError x and y must have length at least 2**: 数据切片后样本量不足

### 4.2 核心差距

#### 差距1：问题一（LMM 模型）

| 对比项 | 生成论文 | 优秀论文 |
|--------|----------|----------|
| 模型选择论证 | ✅ 对比了 OLS/GEE/LMM | ✅ 同样对比，更简洁 |
| 交互效应 | ❌ **未纳入交互项** (Week×BMI) | ✅ 纳入了 t² 项，发现非线性 |
| 其他变量 | ❌ 仅用 Week + BMI | ✅ 纳入了身高 (Height_z) |
| 模型检验 | ✅ ICC=0.35，有诊断图 | ✅ ICC=0.743，有完整的随机效应检验 |
| 随机效应 | 仅随机截距 | ✅ 有完整的正态性检验、同方差检验、LOWESS分析 |

**差距分析**：优秀论文的 LMM 模型更复杂（纳入二次项和身高变量），且模型检验更完整。生成论文的 ICC=0.35 远低于优秀论文的 ICC=0.743，说明模型可能遗漏了重要解释变量。

#### 差距2：问题二（BMI 分组与检测时点优化）

| 对比项 | 生成论文 | 优秀论文 |
|--------|----------|----------|
| 分组方法 | K-means 聚类 | ✅ 遗传算法联合优化分组边界和时点 |
| 达标时间估计 | 直接观测 + 简单预测 | ✅ **高斯过程回归 (GPR)** + 三阶段分层决策 |
| 优化方法 | 期望风险最小化 | ✅ 遗传算法全局优化 |
| 不同准确率场景 | ❌ 仅一个场景 | ✅ **50%/75%/90%/95%/99% 五个场景** |
| 误差分析 | 蒙特卡洛模拟 | ✅ 不同误差容忍度下的策略变化 |
| 结果展示 | 3个最佳时点 | ✅ 完整的分组边界 + 时点 + 风险等级表格 |

**差距分析**：优秀论文在问题二上的方法论远超生成论文。高斯过程回归处理稀疏数据、遗传算法联合优化、多准确率场景分析都是显著的创新点。生成论文的 K-means + 固定风险函数方法过于简单。

#### 差距3：问题三（多因素优化）

| 对比项 | 生成论文 | 优秀论文 |
|--------|----------|----------|
| 方法 | ❌ **误将问题三当作女胎判定** | ✅ 混合深度生存网络 (MLP + LSTM + DeepHit) |
| 特征 | 仅用 Z 值 | ✅ 静态特征 (年龄/身高/体重/BMI) + 时序特征 |
| 模型 | Mahalanobis 距离 | ✅ 生存分析框架，输出达标概率曲线 |

**差距分析**：这是最严重的差距。**生成论文将问题三和问题四搞混了**——问题三应该是在问题二基础上纳入更多因素（身高、体重、年龄）进行男胎检测时点优化，但生成论文将其误读为女胎异常判定。这导致问题三的方法完全偏离了题意。

#### 差距4：问题四（女胎异常判定）

| 对比项 | 生成论文 | 优秀论文 |
|--------|----------|----------|
| 方法 | Mahalanobis + GBDT | ✅ LightGBM 堆叠集成 + 元学习 |
| 架构 | 两个独立模型 | ✅ **四个专项模型 + 元模型 + 逻辑修正层** |

## 五、隐藏问题与改进建议

### 5.1 评分系统异常

**问题**：Reflexion 评分系统初始分数异常高（250-317 分），最终修正到 83-96 分。评分量纲不一致，可能是百分制和千分制混用。

**建议**：检查 `evaluation.py` 中的评分函数，确保所有维度满分一致（建议统一为百分制），并在 Reflexion 阈值判断时使用标准化后的分数。

### 5.2 ResultInterpreterAgent 始终报告 "is_reasonable: false"

**问题**：所有 6 次 ResultInterpreterAgent 调用都返回 `is_reasonable: false`，但工作流仍然继续执行。这说明 ResultInterpreterAgent 的判断结果未被有效利用。

**建议**：当 `is_reasonable=false` 时，应触发 CoderAgent 重新执行代码，而非直接进入下一阶段。

### 5.3 CriticAgent 无 "decision" 字段

**问题**：CriticAgent 的 JSON 响应中没有顶层 `decision` 字段（决策信息在 `critique_chapter_logic` 子工具结果中），但 workflow.py 可能无法正确解析。

**建议**：检查 CriticAgent 的输出格式是否与 workflow.py 中的解析逻辑一致。

### 5.4 问题三题意理解错误

**问题**：生成论文将问题三（男胎多因素优化）误读为女胎异常判定，导致整个章节方法论偏离。

**建议**：
1. 在 CoordinatorAgent 的任务拆解中，明确标注每个子任务对应的问题编号和核心要求
2. 在 ModelerAgent 建模前，增加"题意确认"步骤
3. 在 CriticAgent 评审中增加"题意一致性"检查

### 5.5 公式无编号

**问题**：生成论文中的数学公式没有编号，不符合学术论文规范。

**建议**：在 WriterAgent 的系统提示词中明确要求所有独立公式必须有编号，格式为 `(1)`, `(2)`, ...。

### 5.6 缺少参考文献

**问题**：生成论文没有任何参考文献，降低了学术可信度。

**建议**：
1. LiteratureAgent 检索到的文献应传递给 WriterAgent
2. 在 WriterAgent 提示词中要求引用文献
3. 论文末尾自动格式化参考文献列表

### 5.7 代码执行错误未自动重试

**问题**：8 次代码执行失败中，部分是因列名错误或数据类型问题，但 CoderAgent 未自动修正重试。

**建议**：将代码执行错误信息反馈给 CoderAgent，要求其分析错误原因并生成修正代码。

## 六、专家咨询问题

以下是整理的 8 个问题，可发送给数学建模 Agent 专家：

### 问题 1：题意理解偏差的自动检测
当前 Agent 在问题三上完全偏离了题意（将"男胎多因素优化"误读为"女胎异常判定"）。如何在多 Agent 系统中自动检测并纠正题意理解偏差？是否应该在 CoordinatorAgent 和 ModelerAgent 之间增加一个"题意确认 Agent"？

### 问题 2：Reflexion 评分量纲不一致
当前评分系统中，review_synthesis 的综合分（56-86）与 review_full 的综合分（83-96）量纲不同，且初始评分异常偏高。如何设计一个统一的、可比较的评分体系？是否应该将所有评审维度标准化到同一量纲？

### 问题 3：ResultInterpreterAgent 的有效性
当前 ResultInterpreterAgent 始终报告 `is_reasonable: false`，但其判断结果未被工作流利用。如何设计一个有效的"结果合理性检查"机制？在什么条件下应该触发代码重执行？

### 问题 4：稀疏数据下的达标时间预测
优秀论文使用高斯过程回归 (GPR) 处理每位孕妇仅 1-2 个观测点的稀疏数据。在 LLM Agent 自动建模的场景下，如何让 Agent 自动识别"数据稀疏"问题并选择合适的非参数方法？GPR 的实现复杂度是否适合自动化？

### 问题 5：联合优化 vs 分阶段优化
优秀论文使用遗传算法联合优化 BMI 分组边界和检测时点，而生成论文使用 K-means 聚类 + 固定风险函数的分阶段方法。在自动化建模中，如何引导 Agent 识别"需要联合优化"的问题特征？联合优化的实现复杂度如何控制？

### 问题 6：堆叠集成架构的自动化设计
优秀论文的四模型堆叠架构（专项模型→元模型→逻辑修正）是人工设计的创新。如何让 Agent 自动设计类似的多层集成架构？是否可以通过预定义的"模型模板库"来引导？

### 问题 7：类别不平衡的自动处理
女胎异常判定中异常样本极少，优秀论文通过分层交叉验证和逻辑修正层处理。当前 Agent 未自动识别和处理类别不平衡。如何在 Agent 工作流中自动检测数据分布问题并选择合适的处理策略？

### 问题 8：公式编号与学术规范
生成论文中的数学公式没有编号，不符合学术论文规范。如何在 Prompt 中有效约束 LLM 的输出格式，确保所有独立公式有连续编号？是否应该在后处理阶段自动添加编号？
