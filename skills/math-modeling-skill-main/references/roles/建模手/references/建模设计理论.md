# 建模设计理论

数学建模中的设计理论 —— 模型选择、复杂度控制、组合策略与证据层次。

---

## 1. 模型选择理论

### 1.1 问题-模型匹配矩阵

| 问题本质 | 核心需求 | 推荐模型方向 | 避免的模型 |
|---------|---------|------------|-----------|
| 资源分配 | 在约束下求最优 | 规划模型（LP/IP/NLP） | 神经网络（不透明） |
| 趋势预测 | 推测未来走向 | 时间序列 / 灰色预测 | 深度学习（数据不足时） |
| 方案排序 | 多指标综合打分 | AHP / TOPSIS / 熵权法 | 单一指标方法 |
| 模式发现 | 从数据中找结构 | 聚类 / PCA / 因子分析 | 线性回归（不适用） |
| 因果关系 | 解释"为什么" | 回归分析 / 结构方程 | 纯预测模型 |
| 风险评估 | 衡量不确定性 | 蒙特卡洛 / 概率模型 | 确定性模型 |

### 1.2 模型选择三原则（扩展版）

**原则一：充分性原则**
模型必须能处理题目给出的所有约束条件和数据特征。如果一个模型无法利用题目提供的某类关键数据，它就是不充分的。

**原则二：必要性原则（奥卡姆剃刀）**
在不损失解释力的前提下，选择最简单的模型。每增加一个复杂度层级，都必须带来显著的精度提升或新的分析维度。

**原则三：可沟通性原则**
模型的逻辑链条应当能被非专业人员理解。在数学建模竞赛中，评阅老师的专业背景多元，一个过于晦涩的模型即使数学上完美，也可能在沟通过程中失分。

## 2. 复杂度控制

### 2.1 模型复杂度谱系

```
低复杂度 ←————————————————————————————→ 高复杂度
   线性规划   时间序列   AHP/TOPSIS   神经网络   深度学习
    · 快速      · 可解释    · 直观      · 黑箱      · 高数据需求
    · 透明      · 成熟      · 易沟通    · 强拟合    · 难调试
```

### 2.2 复杂度决策树

```
问题是否需要处理高度非线性关系？
├─ 否 → 线性模型 / 规划模型
└─ 是 → 数据量是否充足（>1000样本）？
       ├─ 是 → 可考虑机器学习模型
       └─ 否 → 灰色预测 / 插值拟合 / 专家系统

问题是否需要高解释性？
├─ 是 → AHP / 回归分析 / 决策树
└─ 否 → 可适当提升复杂度换取精度

问题是否需要实时计算？
├─ 是 → 轻量模型（线性规划 / 简单回归）
└─ 否 → 可接受较长的计算时间
```

### 2.3 复杂度控制的经验法则

- **2个模型法则**：每道题的主模型不超过 2 个（1个主模型 + 1个验证/对比模型）
- **3层嵌套法则**：模型嵌套不超过 3 层（如：模型A的输出 → 模型B的输入 → 模型C的参数）
- **5参数法则**：需要手动调节的参数不超过 5 个，否则调参过程本身会引入不确定性

## 3. 模型组合策略

### 3.1 组合类型

| 组合类型 | 结构 | 适用场景 | 示例 |
|---------|------|---------|------|
| **串联** | A→B→C | 输出作为下一级输入 | 聚类→分类→评价 |
| **并联** | A+B+C→集成 | 多角度分析同一问题 | 多种预测方法加权平均 |
| **主副** | 主模型+辅助分析 | 主模型回答核心问题，辅助模型提供补充信息 | 优化模型+灵敏度分析 |
| **阶梯** | 简单→复杂→验证 | 先用简单模型探索，再用复杂模型精化 | 线性回归→神经网络→交叉验证 |

### 3.2 组合的互补性原则

好的模型组合应当是**互补而非重叠**的：

```
✅ 优秀的组合：
  灰色预测(GM(1,1)) → 预测趋势（"涨多少"）
  + AHP层次分析  → 评价因素（"为什么涨"）
  → 完整回答："涨多少" + "为什么涨"

✅ 优秀的组合：
  遗传算法 → 寻找最优解
  + 蒙特卡洛 → 评估最优解的稳定性
  → 完整回答："最优方案" + "方案可靠吗"

❌ 糟糕的组合：
  线性回归 → 做预测
  + 神经网络 → 做同样的预测
  → 两者都在说同一件事，冗余
```

### 3.3 组合的验证策略

每个模型组合应包含至少一种验证方式：

| 验证方式 | 方法 | 适用场景 |
|---------|------|---------|
| 交叉验证 | 将数据分训练/测试集 | 有足够数据时 |
| 残差分析 | 分析预测值与实际值的差异模式 | 回归类模型 |
| 敏感性分析 | 调整关键参数观察结果变化 | 优化/评价类模型 |
| 对比验证 | 用不同模型求解同一问题并比较 | 所有类型 |
| 稳定性检验 | 对输入数据加微小扰动观察输出变化 | 数据质量不确定时 |

## 4. 证据层次

### 4.1 建模证据金字塔

```
          ╱  ╲
         ╱ 第   ╲         定量验证 + 实际数据
        ╱ 一层  ╲         （最强证据）
       ╱─────────╲
      ╱  第二层   ╲       理论推导 + 仿真模拟
     ╱─────────────╲
    ╱   第三层     ╲      专家判断 + 经验公式
   ╱─────────────────╲
  ╱    第四层        ╲    假设推演 + 定性分析
 ╱─────────────────────╲
```

- **第一层证据**：模型输出与真实数据直接比较（如：预测值 vs 实际值，误差在可接受范围内）
- **第二层证据**：模型的数学推导合理，仿真结果符合预期模式
- **第三层证据**：模型参数取值有领域文献支持，或经专家判断校准
- **第四层证据**：模型在极端条件下的行为符合逻辑预期

### 4.2 在论文中构建证据链

好的数学模型论文不是罗列公式，而是构建一条逻辑证据链：

```
问题定义 → 模型选择理由（为什么这个模型？）
   ↓
模型建立（公式+推导，证据来自数学理论）
   ↓
模型求解（算法+计算，证据来自仿真/优化）
   ↓
结果分析（数据+对比，证据来自定量验证）
   ↓
模型评价（优缺点+灵敏度，证据来自多角度检验）
```

每一环都要回答"为什么"：

| 环节 | 必须回答的问题 |
|------|--------------|
| 模型选择 | 为什么这个模型适合这个问题？ |
| 模型建立 | 为什么这个公式能描述该现象？ |
| 模型求解 | 为什么这个算法能找到最优解？ |
| 结果分析 | 为什么结果可信？与什么对比？ |
| 模型评价 | 为什么模型在多种条件下都稳定？ |

## 5. 模型风险与局限性

### 5.1 常见模型风险

| 风险类型 | 表现 | 缓解策略 |
|---------|------|---------|
| 过拟合 | 模型在训练数据上表现优秀，但泛化能力差 | 交叉验证、正则化、简化模型 |
| 欠拟合 | 模型过于简单，无法捕捉数据中的模式 | 增加特征、更换更灵活的模型 |
| 数据偏差 | 训练数据不能代表真实场景 | 数据增强、敏感性分析 |
| 参数敏感 | 微调参数导致结果剧烈波动 | 稳定性检验、区间估计 |
| 假设不成立 | 模型的核心假设与实际情况不符 | 替代假设检验、非参数方法 |

### 5.2 局限性声明的标准句式

在分析文档和论文中，对每个模型都应包含局限性声明：

> "本模型的局限性在于[具体假设/条件]，在[某些场景]下可能不适用。但通过[缓解策略]，在[有效范围]内结果仍然是可靠的。"

## 6. 设计评审原则

### 6.1 评审维度

| 维度 | 检查项 | 通过标准 |
|------|-------|---------|
| 完整性 | 模型是否覆盖了题目的所有要求 | 所有问题/约束都有对应模型处理 |
| 一致性 | 不同模型之间是否存在矛盾 | 模型的假设前提兼容，输出不冲突 |
| 敏感性 | 结果是否对参数变化过于敏感 | 关键参数变化±10%时，结果变化方向合理 |
| 可解释性 | 模型的每一步推理是否可追溯 | 能说出每个变量和参数的实际含义 |

### 6.2 评审输出

每次评审应产出三项内容：

1. **通过/有条件通过/不通过** 的判断
2. **改进建议**（如有）
3. **遗留风险**（已知但未解决的问题，需在论文中说明）
