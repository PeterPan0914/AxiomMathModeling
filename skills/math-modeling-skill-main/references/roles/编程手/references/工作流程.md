## 工作流程

### 第一步：理解需求

1. 读取建模分析文档：理解建模手的分析结果
2. 确认编程语言：Python 或 MATLAB（如果未指定，询问用户）
3. 理解题目要求：读取题目文件，明确需要解决的问题

### 第二步：环境检查（必须先执行）

在编写任何代码之前，检查所选编程语言的运行时环境和依赖包。

**Python 环境检查**：
```python
# 检查 Python 版本
import sys
print(f"Python 版本: {sys.version}")

# 检查必需包
required_packages = [
    'numpy', 'pandas', 'matplotlib', 'scipy',
    'sklearn', 'statsmodels', 'openpyxl',
]

for package in required_packages:
    try:
        __import__(package)
        print(f"✅ {package} 已安装")
    except ImportError:
        print(f"❌ {package} 未安装，请运行: pip install {package}")
```

**MATLAB 环境检查**：
```matlab
% 检查 MATLAB 版本
version

% 检查工具箱
toolboxes = {'optimization_toolbox', 'statistics_toolbox', 'symbolic_toolbox'};
% 使用 license 或 ver 命令检查
```

**检查规则**：
- 如果选择的运行时或必需的包不可用，**先报告确切的问题**，然后提供安装命令
- **不要因为环境问题而切换到另一种语言**（如 Python 不可用就改 MATLAB）
- 如果用户批准安装依赖，安装后继续；如果无法安装，报告阻碍并等待指示
- 可视化相关：确保 `matplotlib` 和 `pillow` 已安装（Python），或 `export_fig` 可用（MATLAB）

### 第三步：代码设计

1. **模块划分**: 将代码划分为清晰的功能模块
2. **数据结构**: 设计合理的数据结构和变量命名
3. **算法实现**: 确定具体的算法实现方法
4. **可视化规划**: 按以下三类系统规划需要绘制的图表，确保每类至少 1-2 张图：

   **① 原始数据可视化**（EDA 阶段，数据拿来先画图）
   - 数据分布：直方图、箱线图、密度图 → 了解数据范围和异常值
   - 相关性分析：热力图、散点图矩阵 → 发现变量间关系
   - 时序趋势：折线图 → 观察数据随时间的变化模式
   - 组成结构：饼图、堆叠柱状图 → 了解数据构成

   **② 中间产物可视化**（模型运行阶段，展示求解过程）
   - 收敛曲线：迭代次数 vs 目标函数值 → 展示优化过程
   - 模型对比：分组柱状图 → 不同模型在同一指标下的性能对比
   - 参数分析：灵敏度折线图 → 参数变化对结果的影响
   - 误差分析：残差图、QQ 图 → 验证模型假设
   - 混淆矩阵：热力图 → 分类模型评估

   **③ 最终结果可视化**（核心结论，论文直接使用）
   - 最终方案对比：柱状图→ 展示不同方案的最终指标
   - 预测结果展示：折线图+置信区间 → 实际值与预测值对比
   - 综合排名/评价：雷达图、气泡图 → 多维度综合展示
   - 地理分布：地图热力图 → 空间数据分析
   - 结果汇总表+趋势：组合图 → 最终结论的核心视觉支撑

   **规划原则**：每类至少 1 张图，每题至少 3-5 张图。先列清单（如："问题1：箱线图(原始数据) + 收敛曲线(中间) + 柱状图对比(最终)"），再开始编码。

### 第四步：代码实现

**代码运行与调试流程**：

```
编写代码 → 运行代码
  ↓
检查是否有报错？
  ├─ 有报错 → 直接在代码文件中修正 → 重新运行
  └─ 无报错 → 继续
  ↓
判断运行结果正确性
  ├─ 结果正确 → 完成
  └─ 结果错误 → 检查代码 → 在代码文件中修正 → 重新运行
```

**严禁投机取巧**：
- ❌ 禁止创建简化版代码（如 `问题一_简化版.py`）
- ❌ 禁止因报错而降低问题难度或更换不合适的算法
- ❌ 禁止更换算法逃避（因原算法报错而换成不合适的简单算法）

### 第五步：结果验证

每道题代码运行后必须进行结果验证：
- 结合题目要求检查结果
- 结合建模分析文档验证
- 结合运行效果检查可视化图表是否合理

### 第六步：迭代改进

如果结果不正确，必须先改进代码再进行下一个问题。

## 表格文件处理规范

| 表格类型 | 处理原则 |
|---------|---------|
| **题目附带输入表格** | 只读不写，禁止修改 |
| **结果输出表格** | 保持结构不变，只填写数据 |

**重要原则**：
- 使用 Excel 公式而非硬编码值
- 不添加/删除列或修改列名
- 输出到新文件，不覆盖原文件
- 使用 xlsx skill 的 recalc.py 重新计算公式
